# Security reporting

Use synthetic examples and keep credentials, personal records, private messages, file inventories and completed worksheets out of public issues and patches.

Use the [private vulnerability report](https://github.com/weidufanling/weidu-drive-helper/security/advisories/new) for this repository. Private reporting was enabled and verified on 31 October 2026. Before submitting, confirm that GitHub still marks the report as private and that it belongs to the correct repository. If that route is unavailable, ask the owner for a private reporting route through an existing trusted conversation. Do not open a public issue containing an exploit, secret or sensitive record. No response time or monitored security inbox is promised.

Give the affected version, a minimal description, the impact you observed and a safe reproduction using invented data. Do not send real credentials or full personal files. Acknowledge what has not been tested.

The repository's checks support review. They are not an independent security audit or a guarantee of suitability. See [the release security checks](RELEASE-SECURITY.md) for the actual check scope and the settings still requiring owner review.
